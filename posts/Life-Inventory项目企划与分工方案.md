## 一、项目背景

在日常生活中，常见痛点包括：

1. 物品随手放置后难以回忆具体位置。
2. 柜子、抽屉、收纳盒层级复杂，查找成本高。
3. 查找依赖记忆与翻找，效率低。
4. 对已有物品缺乏全局认知，容易重复购买。

核心问题：

人类依赖空间记忆，但缺乏易用的数字化辅助工具。

项目目标：

构建一个以空间可视化为核心的个人物品管理系统，帮助用户快速、准确定位物品。

## 二、项目简介

个人物品可视化管理系统（Life Inventory）是一款以图片交互和智能搜索为核心的应用。

系统将现实中的收纳空间数字化，建立物品与存储位置的映射关系，实现：

1. 可视化管理空间。
2. 结构化管理物品。
3. 搜索反查具体位置。
4. 在此基础上扩展智能推荐和图像识别。

## 三、核心功能设计

### 1. 空间可视化管理（核心）

1. 用户上传存储空间图片（柜子、抽屉、书桌等）。
2. 在图片上添加标注点、箭头或热点区域。
3. 每个标注绑定一个区域或一组物品。
4. 点击标注可查看该位置物品详情。

价值：

实现所见即所得的定位方式。

### 2. 物品管理系统

1. 物品增删改查。
2. 记录名称、分类、标签、描述、图片。
3. 支持状态管理：在库、已取出、已迁移。
4. 支持迁移记录与位置更新。

### 3. 智能搜索功能

1. 全局搜索与局部搜索。
2. 关键词匹配。
3. 模糊匹配（名称不完整或近似拼写）。
4. 搜索结果直接关联到空间位置。

价值：

实现从物品到位置的快速反查。

### 4. 重要物品与收藏夹

1. 对证件、药品等重要物品打标。
2. 提供重要物品集合页。
3. 支持加密保护。
4. 设置访问密码后才能查看敏感位置。

### 5. 过期提醒（扩展）

1. 支持食品、药品等设置过期时间。
2. 即将过期时自动提醒。

### 6. Agent 智能推荐（扩展）

1. 场景化查询：例如感冒、画画、出行等。
2. 系统根据库存与标签返回候选物品。
3. 从查找升级为辅助决策。

### 7. 图像辅助识别（可选扩展）

1. 上传物品照片。
2. 系统识别并给出名称建议。
3. 用户确认后快速录入。

## 四、系统特点

1. 空间驱动的数据组织方式，更符合人类认知。
2. 图片交互体验强，定位直观。
3. 搜索作为核心入口，提升查找效率。
4. 轻量智能能力可先用规则与标签实现。
5. 架构可扩展，后续可接入更强 AI 能力。

## 五、应用场景

1. 宿舍与家庭收纳管理。
2. 学习用品与电子设备整理。
3. 药品与日用品管理。
4. 兴趣工具管理（绘画、摄影、手工）。
5. 小型个人仓库管理。

## 六、目标用户

1. 记忆混乱但有整理需求的用户。
2. 宿舍与合租环境中的学生群体。
3. 对物品位置管理有高频需求的人群。

## 七、项目目标

本项目的核心目标是：

让用户快速、准确知道某个东西在哪里。

中长期目标：

从记录工具演进为生活助手。

## 八、项目分工方案（6人）

## 1. 总体分工原则

项目应围绕四个系统层推进，而非按零散功能拆分：

1. 前端交互系统。
2. 后端系统。
3. 核心数据逻辑。
4. 智能扩展系统。

关键原则：

分工按系统层，不按碎片功能。

## 十、MVP 范围控制

必做功能：

1. 图片上传。
2. 标注位置。
3. 物品绑定。
4. 搜索定位。
5. 存入、取出、迁移。

可选功能：

1. 收藏夹。
2. 过期提醒。
3. 场景推荐。

暂不做功能：

1. 高复杂度 AI 系统。
2. 全自动识别全部物品。

## 十一、技术栈建议（适合 0 基础）

前端：

1. React。
2. Ant Design。

后端：

1. Node.js。
2. Express。

数据库：

1. SQLite（优先，轻量、易部署）。
2. MySQL（进阶）。

AI 扩展：

1. 第三方 API 调用。
2. 不做模型训练。

## 十二、项目难点与风险

主要难点：

1. 标注坐标系统。
2. 数据模型设计。
3. 搜索体验与命中率。

风险控制建议：

1. 先做可用，不追求一开始全自动识别。
2. 明确接口规范，严禁私改数据结构。
3. 先保证主链路稳定，再做扩展加分项。
