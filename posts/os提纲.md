## 第二章

### 2.1 进程

#### 2.1.1 + 2.1.2 进程的概念、组成、特征

进程是系统进行资源分配和调度的一个独立单位。

1. 进程的概念
   程序是静态的，是存在磁盘上的可执行文件；进程是动态的，是程序的一次执行过程。

2. 进程的组成

- PCB、PID
- 程序段
- 数据段

PCB 即进程控制块，操作系统需要对各个并发的进程进行管理，凡是管理所需要的信息都会放在 PCB 中。

3. 进程的特征

- 动态性：进程的最基本特性
- 并发性
- 独立性：独立获得资源、独立接受调度的基本单位
- 异步性
- 结构性

#### 2.1.3 进程的状态与转换

1. 状态

- 三种基本状态：运行状态、就绪状态、阻塞状态
- 其他状态：创建状态、终止状态

2. 状态间的转换

- 不能由阻塞态直接转换为运行态
- 不能由就绪态直接转换为阻塞态
- 运行态到阻塞态是一种进程自身做出的主动行为

3. 进程的组织方式

- 链接方式
- 索引方式

#### 2.1.4 进程控制

1. 进程控制的实现

- 原语：过程需要一气呵成，执行具有原子性，期间不允许被中断
- 原理：通过关中断和开中断这两个特权级指令实现原子性

2. 进程的创建

- 创建原语：申请空白 PCB、为新进程分配所需资源、初始化 PCB、将 PCB 插入就绪队列
- 引起进程创建的事件：用户登录、作业调度、提供服务、应用请求

3. 进程的终止

- 撤销原语：
  - 从 PCB 集合中找到终止进程的 PCB
  - 若进程正在运行，立即剥夺 CPU，将 CPU 分配给其他进程
  - 终止所有子进程
  - 将该进程所拥有的所有资源归还给父进程或操作系统
  - 删除 PCB
- 引起进程终止的事件：正常结束（exit 系统调用）、异常结束（除以 0）、外界干预（用户杀掉进程）

4. 进程的阻塞

- 阻塞原语：找到进程 PCB，保护进程运行现场，将 PCB 设置为阻塞态并插入相应等待队列
- 引起进程阻塞的事件：
  - 需要等待系统分配某种资源
  - 需要等待相互合作的其他进程完成工作

5. 进程的唤醒

- 唤醒原语：
  - 在等待队列中找到 PCB，从等待队列移除，设置为就绪态
  - 将 PCB 插入就绪队列，等待被调度
- 引起进程唤醒的事件：等待事件的发生

6. 进程切换

- 切换原语：
  - 将运行环境信息存入 PCB
  - PCB 移入相应队列
  - 选择另一个进程执行，并更新其 PCB
  - 根据 PCB 恢复新进程所需的运行环境
- 引起进程切换的事件：
  - 当前进程时间片到
  - 有更高优先级的进程到达
  - 当前进程主动阻塞
  - 当前进程终止

### 2.2 调度

#### 2.2.1 调度的概念和层次

1. 概念
   一堆任务要处理，但资源有限，无法同时处理，需要确定某种规则来决定处理任务的顺序，这就是调度研究的问题。

2. 调度的三个层次

- 高级调度（作业调度）
- 低级调度（进程调度/处理机调度）
- 中级调度（内存调度）

补充：

- 进程的挂起态与七状态模型
- 为了减轻系统负载，暂时不执行的进程会被调到外存，从而变成挂起态
- 挂起和阻塞的区别：阻塞态进程映像还在内存中，挂起态则调到外存

3. 三层调度的联系和对比
   要做什么、调度发生位置、发生频率、对进程状态的影响。

#### 2.2.2_1 进程调度（低级调度）

1. 时机

- 需要进行进程调度与切换的情况：主动放弃、被动放弃
- 不能进行切换的情况：处理中断、操作系统内核程序临界区、原子操作过程

2. 切换与过程

- 狭义的进程调度：在就绪队列中选中一个要运行的进程（可能是刚刚被暂停执行的进程，也可能是另一个进程；后者需要进程切换）
- 进程切换：一个进程让出处理机，另一个进程占用处理机
- 广义的进程调度：包含“选择一个进程 + 进程切换”两个步骤
- 切换过程主要完成：旧进程数据保存、新进程数据恢复
- 进程切换越频繁，效率越低，真正执行进程的时间越少

3. 方式

- 非剥夺调度方式（非抢占方式）：只允许进程主动放弃
- 剥夺调度方式（抢占）：强行打断正在运行的进程，把 CPU 分给别的进程

补充：

- 临界资源：一个时间段内只允许一个进程使用的资源，各进程需要互斥访问
- 临界区：访问临界资源的代码
- 内核程序临界区一般用来访问某种内核数据结构，比如进程的就绪队列（由各就绪进程的 PCB 组成）

#### 2.2.2_2 调度器、闲逛进程

1. 调度时机（什么事件会触发调度程序）

- 创建新进程
- 进程退出
- 运行进程阻塞
- I/O 中断发生（可能唤醒某些阻塞进程）

2. 闲逛进程

- 优先级最低
- 可以是 0 地址指令，占据一个完整的指令周期
- 能耗低

#### 2.2.3 调度的目标（评价指标）

1. CPU 利用率（可用甘特图辅助计算）
2. 系统吞吐量
3. 周转时间 = 作业完成时间 - 作业提交时间
4. 带权周转时间 = 作业周转时间 / 作业实际运行时间
5. 等待时间：进程/作业处于等待处理机状态时间之和，等待时间越长，用户满意度越低
6. 响应时间：用户提交到首次响应所需的时间

补充：作业和进程在等待时间上的计算不同。

#### 2.2.5_1 调度算法 1

对比维度：算法思想、算法规则、用于作业调度还是进程调度、是否抢占式、优缺点、是否会导致饥饿。

1. 先来先服务（FCFS）

- 非抢占式

2. 短作业优先（SJF）

3. 高响应比优先（HRRN）

#### 2.2.5_2 调度算法 2

对比维度：算法思想、算法规则、用于作业/进程调度、是否可抢占、优缺点、是否会导致饥饿。

1. 时间片轮转
   这种算法属于抢占式，由时钟装置发出时钟中断来通知 CPU 时间片已到。

2. 优先级调度算法

- 抢占式：只要来了一个更高优先级的进程，就立即抢占当前进程；就绪队列发生改变时也需要检查是否会发生抢占
- 非抢占式：即使来了更高优先级的进程，也要等当前进程运行结束或主动让出 CPU
- 优先级有静态调整和动态调整

如何合理设置各类进程的优先级：

- 系统进程优先级高于用户进程
- 前台进程优先级高于后台进程
- 操作系统更偏向 I/O 型进程（I/O 设备和 CPU 可并行工作，若让 I/O 繁忙型进程优先，越可能让 I/O 更早投入工作，资源利用率和系统吞吐量都会提升）
- 有可能导致饥饿
