# 文件路径书写：把 Linux 命令和 Makefile 依赖一次讲清楚

你遇到的“路径”，本质上通常不是记忆问题，而是这 3 个概念：

- 你现在站在哪（当前工作目录，cwd）
- 你写的是绝对路径还是相对路径
- 这个路径是给谁看的（shell、make、编译器、链接器）

只要把这三件事分开，路径问题会一下子清晰很多。

---

## 1. 先记住一个总原则

**相对路径永远是“相对于当前工作目录”解释的，不是相对于你心里想的目录。**

在 Linux 里，先用：

```bash
pwd
```

确认你当前在哪，再写路径。

---

## 2. 路径的两种写法

## 2.1 绝对路径

从根目录 `/` 开始写，和你站在哪里无关。

例子：

```text
/home/user/oslab/src/kernel/main.c
```

特点：

- 不会因为 `cd` 变化而失效
- 可读性高
- 太长，迁移项目时不够灵活

## 2.2 相对路径

不以 `/` 开头，基于当前目录解释。

常用符号：

- `.` 当前目录
- `..` 上一级目录

例子：

```text
src/kernel/main.c
../include
./run/hd.img
```

---

## 3. 先学会“画目录树 + 站位”

假设工程结构是：

```text
oslab/
	src/
		boot/
			mbr.asm
		kernel/
			main.cpp
	include/
	run/
		hd.img
	build/
	Makefile
```

如果你当前在 `oslab/`：

- `src/boot/mbr.asm` 正确
- `../src/boot/mbr.asm` 错误（会跑到上一级）

如果你当前在 `oslab/build/`：

- `../src/boot/mbr.asm` 正确
- `src/boot/mbr.asm` 错误

所以路径正确与否，先看“你站在哪”。

---

## 4. Linux 命令里的路径怎么判断

## 4.1 `cat/cp/mv/rm/gcc/ld` 等命令

这些命令里的相对路径，都是相对于你执行命令时 shell 的当前目录。

例如：

```bash
cd /home/user/oslab
gcc -c src/kernel/main.cpp -o build/main.o
```

这里 `src/...` 和 `build/...` 都相对于 `/home/user/oslab`。

## 4.2 快速排错三件套

路径错了就立刻做：

```bash
pwd
ls
ls src/boot
```

大多数路径问题 10 秒内能定位。

---

## 5. Makefile 里的路径：最容易混淆的部分

结论先给：

- Makefile 里的依赖路径（冒号右边）由 make 解析，通常也是相对当前执行 make 的目录。
- 配方命令（tab 开头那几行）由 shell 执行，shell 再按自己的 cwd 解释路径。
- 默认情况下，你在项目根目录执行 `make`，二者看到的 cwd 一般一致。

例子：

```makefile
SRCDIR = src
BUILDDIR = build

main.o: $(SRCDIR)/kernel/main.cpp
	g++ -c $(SRCDIR)/kernel/main.cpp -o $(BUILDDIR)/main.o
```

如果你在项目根目录执行 `make`，这段通常没问题。

---

## 6. 写 Makefile 路径的推荐套路

## 6.1 先定义“根”再拼接

```makefile
ROOT := .
SRCDIR := $(ROOT)/src
INCDIR := $(ROOT)/include
BUILDDIR := $(ROOT)/build
RUNDIR := $(ROOT)/run
```

好处：

- 路径统一
- 迁移目录只改一处

## 6.2 源码目录和构建目录分离

```makefile
$(BUILDDIR)/%.o: $(SRCDIR)/%.c
	@mkdir -p $(dir $@)
	gcc -c $< -o $@
```

这样不会把 `.o` 弄到源码目录。

## 6.3 include 路径和源文件路径不要混用

```makefile
CFLAGS += -I$(INCDIR)
```

- `-I` 是给编译器头文件搜索路径
- 不是源文件路径替代

---

## 7. 你在 OS 实验里最常见的路径错误

## 7.1 `../` 用多了或少了

症状：`No such file or directory`

处理：

- 先 `pwd`
- 再按目录树数层级，不要靠感觉

## 7.2 在 Makefile 里把“源文件相对路径”和“输出文件相对路径”写反

比如你在根目录执行 make，却把输出写成 `../build/xxx.o`，会跑到项目外。

## 7.3 链接阶段找不到对象文件

常见原因：

- 编译阶段输出在 `build/src/...`，链接阶段却写成 `build/...`
- 文件名同名覆盖（如多个 `init.o`）

## 7.4 `dd` 写镜像路径错

你以为写的是 `run/hd.img`，实际 cwd 不对写到了别处。

建议先：

```bash
realpath run/hd.img
```

确认绝对路径再执行破坏性操作。

---

## 8. 一套实战检查法（建议每次都用）

执行构建前：

1. `pwd`：确认当前目录
2. `ls`：确认关键目录在不在
3. `make print-vars`：打印关键变量（SRCDIR/BUILDDIR/OBJ）
4. `make -n`：先看将执行的命令，不真正执行

这个流程能避开 80% 路径错误。

---

## 9. 最后用一句话记住

路径从来不是“对不对”的玄学，而是一个确定计算：

**最终路径 = 当前工作目录 + 你写的路径表达式（再经过 make/shell/编译器各自解释）。**

你以后只要每次先问自己两句：

- 我现在站在哪？
- 这个路径是给谁解释的？

路径问题就会非常稳定。
